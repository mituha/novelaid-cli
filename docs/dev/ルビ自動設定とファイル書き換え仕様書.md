# ルビ自動設定とファイル書き換え仕様書

本ドキュメントは、小説執筆補助CLIツール（`novelaid-cli`）において、Pi Coding Agent SDK の核心機能である**「AI対話を通じた原稿ファイルの自律的な読み込み・推論・書き換え」**を実証するための設計仕様書です。
隣接リポジトリ [`novelaid-ruby`](../novelaid-ruby-ts) の構文規則および実装資産を活用し、原稿ファイルへの「ルビ自動設定機能」を先行して開発・検証します。

---

## 1. 背景と目的

これまで `novelaid-cli` では、作業フォルダーの移動（`/cd`）、フォルダー種別（`NovelaidDocumentType`）の自動分類、およびAIへの現在地・文脈動的注入（`before_agent_start`）という**コンテキスト基盤**を整えてきました。

次のステップとして、**「AIがユーザーとの対話を通じて原稿ファイル（`.txt` / `.md`）を読み込み、自律的に判断して安全にファイルを書き換える（エージェントループが実動作する）」**ことを検証します。

### ルビ自動設定を先行課題とする理由
1. **テキスト破壊リスクの低さ**: 文章の大規模なリライトと異なり、親文字を残したまま前後に記号（`|` と `《》`）を補う差分置換であるため、安全にテストしやすい。
2. **小説執筆における実用性の高さ**: 難読漢字、作中固有の人物名・地名・魔法名、当て字（例: `｜本気《マジ》`）など、Web小説や出版原稿において作家が最も手間をかける作業の1つである。
3. **実証済みライブラリの存在**: 隣接プロジェクト `novelaid-ruby`（`../novelaid-ruby-ts`）の正規表現パターンおよびパーサー資産をそのまま活用できる。

## 2. 小説執筆補助機能の体系一覧

AIが原稿ファイルの読み書きに関与する機能群として、以下の5大支援機能を定義します。

```mermaid
flowchart TD
    subgraph "AI対話 ＆ ファイル書き換え機能群"
        F1["① ルビ自動設定（先行実証）<br/>難読漢字・固有名詞・当て字のふりがな付与"]
        F2["② 誤字脱字・表記揺れチェック<br/>同音異義語・送り仮名・タイポ検出と修正"]
        F3["③ 文体・リズム校正（推敲支援）<br/>語尾重複・受身使役是正・情景描写補強"]
        F4["④ キャラクター口調・設定整合性<br/>設定資料とセリフの突合・ブレ検出"]
        F5["⑤ サブタイトル・あらすじ生成<br/>読者誘引タイトル・章要約のメタデータ追記"]
    end

    F1 -->|"書き換え基盤の実証"| F2
    F2 --> F3
    F3 --> F4
    F4 --> F5
```

| 機能 | 概要 | ファイル操作 |
|---|---|---|
| **① ルビ自動設定（最優先）** | 難読漢字、作中固有名詞（人名・地名・技名）、当て字を文脈から判定し、ルビ記法を挿入。 | 本文の局所差分置換（`edit`） |
| **② 誤字脱字・表記揺れ修正** | 同音異義語の誤変換（「意外／以外」等）、送り仮名の不統一、固有名詞の誤記を検出・修正。 | 本文の局所差分置換（`edit`） |
| **③ 文体・リズム校正** | 語尾の過度な重複（「〜だった。〜だった。」）、受身・使役の過剰使用、冗長表現の推敲。 | 段落単位の差分置換（`edit`） |
| **④ 口調・設定整合性チェック** | `00_settings/` のキャラクター設定（一人称・口調）と本文セリフを対比しブレを修正。 | 設定参照 ＋ セリフ置換（`edit`） |
| **⑤ サブタイトル・あらすじ生成** | 本文要約から読者を引きつける各話サブタイトルやWeb投稿用あらすじを生成・追記。 | 原稿先頭やFront Matterへの追記 |

## 3. ルビ自動設定（`novelaid-ruby` 連携）仕様

### 3.1 採用するルビ記法規則
[`novelaid-ruby`](../novelaid-ruby-ts/src/core/patterns.ts) の仕様に完全準拠します。日本の主要小説投稿サイト（カクヨム、小説家になろう、ノベルアップ+等）および青空文庫で標準的に解釈される記法です。

1. **パイプありルビ（標準推奨）**:
   - `|親文字《ルビ》` または `｜親文字《ルビ》`
   - 例: `|刹那《せつな》`, `|アレン《勇者》`, `|本気《マジ》`
   - 親文字の開始位置を曖昧さに頼らず厳密に確定できるため、AI置換において最優先で使用します。
2. **パイプなし漢字ルビ**:
   - `漢字《ルビ》`
   - 例: `憂鬱《ゆううつ》`
   - 漢字の直後に《》が続く形式。
3. **傍点（圏点）**:
   - `《《強調文字列》》`
   - 例: `《《絶対に》》`

### 3.2 ルビ付与の品質ガイドライン（過剰ルビの防止）
AIが無差別にあらゆる漢字にルビを振ってしまう「ルビ公害」を防ぐため、以下の執筆ルールをシステムプロンプト・ツールに組み込みます。

1. **初出優先の原則**:
   - 1話（1ファイル）の中で同じ単語が複数回登場する場合、**原則として最初の1回（初出時）のみルビを振る**。
2. **既存ルビの重複回避**:
   - すでに `|漢字《かんじ》` や `漢字《かんじ》` と書かれている箇所には絶対に二重にルビを振らない（`novelaid-ruby` の `RUBY_PATTERNS` で既存ルビを保護）。
3. **対象の選定基準**:
   - ① 常用漢字表外、または小学校・中学校で習わない難読漢字（例: `|躊躇《ちゅうちょ》`, `|齟齬《そご》`, `|朦朧《もうろう》`）。
   - ② 作中固有の読み方、ファンタジー固有名詞（例: `|聖剣《エクスカリバー》`, `|黒炎《ダーク・フレイム》`）。
   - ③ キャラクター名（読者が初見で読めない可能性がある人名・地名）。
   - ④ 意図的な当て字。

## 4. AI対話とファイル書き換えの処理シーケンス

Pi SDK の標準ツール（`read`, `edit`, `write`）および拡張フック（`before_agent_start`）を活用した対話フローです。

```mermaid
sequenceDiagram
    autonumber
    actor User as 作家（ユーザー）
    participant CLI as novelaid-cli (TUI)
    participant Agent as AIエージェント
    participant Tool as Pi SDK File Tools
    participant FS as 原稿ファイル (.txt/.md)

    User->>CLI: 「第1話.txt の難読漢字にルビを振って」
    CLI->>Agent: before_agent_start (現在地・ルビ付与ガイドライン注入)
    Agent->>Tool: read (path: "10_novels/第1話.txt")
    Tool->>FS: ファイル読み込み
    FS-->>Tool: 原稿テキスト返却
    Tool-->>Agent: 本文テキスト

    Note over Agent: 文脈解析・難読語抽出<br/>novelaid-ruby記法で差分生成
    Agent->>Tool: edit (path: "10_novels/第1話.txt", edits: [...])
    Tool->>CLI: 差分プレビュー表示（Diff UI）
    CLI->>User: 変更内容の確認表示
    User-->>CLI: 承認 (Enter)
    Tool->>FS: ファイル書き換え適用
    FS-->>Tool: 完了通知
    Tool-->>Agent: 編集完了
    Agent-->>User: 「第1話の3箇所にルビを付与しました。（1. ｜躊躇《ちゅうちょ》...）」
```

## 5. 開発計画（実装ステップ）

1. **Step 3-5a: `novelaid-ruby` 構文の組み込みとルビ支援プロンプト/ツールの設計**:
   - 小説原稿フォルダーでの執筆ペルソナに「ルビ振り支援ガイドライン」を統合。
   - スラッシュコマンド `/ruby [ファイル名]` または自然言語プロンプトの受付基盤を整備。
2. **Step 3-5b: テスト原稿を用いた対話・ファイル書き換え実証テスト**:
   - `test-novel/` 等の原稿に対して「難読漢字へのルビ振り」「固有名詞へのルビ振り」を実行。
   - `read` ➔ `edit` 差分置換 ➔ ファイル永続化の正常動作とロールバック可能性を検証。
3. **Step 3-5c: 誤字脱字チェック・文体校正への横展開**:
   - 実証されたファイル書き換えパイプラインを誤字脱字修正や推敲機能へ横展開。
